# openEagle 开发指南

## 1. 环境要求

- Node.js（建议使用 `corepack` + `pnpm@10.7.0`）
- Python `>=3.12`
- `uv`（用于后端依赖与构建）
- Rust / Cargo（Tauri 开发）

## 2. 本地启动

```powershell
corepack enable
corepack prepare pnpm@10.7.0 --activate
pnpm install
uv sync --project .\backend
pnpm tauri:dev
```

## 3. 编码与文件规范（强约束）

- 所有文件读写必须使用 `UTF-8`（无 BOM）。
- 在 Windows 下执行写文件前，先确认控制台编码：

```powershell
chcp 65001
```

- 禁止使用默认编码、GBK、ANSI。
- 如果发现中文乱码，先确认正确原文来源（历史版本/上下文）后再改，不能“猜测修复”。

## 4. 关键架构

### 4.1 进程与连接

- Tauri Rust 启动 Python sidecar。
- 后端启动后输出握手日志：`[AGENT_READY] WS_PORT: <port>`。
- 前端建立 `ws://127.0.0.1:<port>/ws`。

### 4.2 SOLO 流程

1. 前端发送 `client:start_solo`。
2. 后端截图、VL 决策、下发 `server:solo_step`。
3. 执行动作并通过 `server:trace`、`server:solo_status` 回传。
4. 遇到危险动作进入 `server:solo_confirmation_required`。

### 4.3 Main/Sub-Agent Runtime

- 普通 `client:send_message` 与 IM 文本消息先进入 `AgentRuntime`。
- `AgentRouter` 负责输出路由决策：直接回答、创建 worker、复用 worker、启动 SOLO 或控制 SOLO。
- `SubAgentManager` 使用内部 scoped conversation id：`<conversation_id>:worker:<worker_id>`，让 worker 上下文保持干净。
- `general` / `research` worker 可保守并发；`coding` 与写入类任务串行；SOLO 全局单实例。
- 前端通过 `server:trace` 展示 `kind="agent"` 的 main-router 与 worker 摘要；工具确认仍沿用原有 confirmation 机制。

### 4.4 显示器选择与预览

- 前端可发送 `client:list_solo_displays` 获取显示器列表与实时预览。
- 设置中的 `solo.preferredDisplayIndex` 会通过 `client:update_settings` 同步到后端。
- 后续 SOLO 截图按该显示器执行。

### 4.5 远程 IM 入口

- 后端 `IMBridge` 负责飞书与 Telegram 的消息接入、白名单校验、会话绑定和回复路由。
- 飞书使用长连接机器人：`feishu.appId` / `feishu.appSecret` 用于连接，`allowedOpenIds` 与 `allowedChatIds` 用于放行用户或会话。
- Telegram 使用 Bot API 长轮询：`telegram.botToken` 用于连接，`allowedUserIds` 与 `allowedChatIds` 用于放行用户或会话。
- 白名单为空时拒绝所有远程来源；最近被拦截的 ID 会通过 `server:im_status` 回到设置页，便于复制配置。
- 远程普通文本默认按 SOLO 任务处理；`/chat <内容>` 才进入 Chat。`/pause`、`/resume`、`/stop`、`/allow`、`/reject` 用于控制当前远程 SOLO。
- 飞书 SDK 的 WebSocket 客户端使用模块级 asyncio loop，必须绑定到独立线程中的专用 loop，避免复用 FastAPI 主事件循环。

### 4.6 SOLO 稳定性策略

- `action_signature` 用于判断真正重复的动作，避免把不同坐标的点击误判为同一动作。
- SOLO step outcome 分为 `success` / `no_op` / `uncertain` / `failed`，恢复早于暂停。
- recovery mode 只给模型换路线提示，不接管模型每一步；进入 recovery mode 后会临时抑制 batch actions。
- `open_url`、点击、双击、`press_keys` 会在动作后做短暂截图稳定采样，尽量把页面加载完成后的画面交给下一轮决策。
- 动作参数格式错误、工具执行失败等可修复问题会写入当前 agent 历史，让 agent 重新决策；连续失败达到阈值才暂停给用户。
- 完成或暂停时写入 `stability_summary`，用于后续定位卡住、重复动作和截图无变化问题。

## 5. 图片显示说明

为避免 `asset.localhost` 在部分机器上访问临时目录出现 `404`，项目增加了 Rust 命令 `read_image_data_url`：

- 前端优先将本地截图路径转换为 `data:image/...;base64` 再渲染。
- 该机制用于设置页显示器预览以及对话中的 SOLO 截图预览。

## 6. 常用检查命令

前端：

```powershell
pnpm -s tsc --noEmit
pnpm -s build
```

后端：

```powershell
backend\.venv\Scripts\python.exe -m compileall backend\app
backend\.venv\Scripts\python.exe -m unittest discover -s backend\tests
```

Rust：

```powershell
cd .\src-tauri
cargo check
```

## 7. 提交流程建议

```powershell
git status
git add <files>
git commit -m "feat: <summary>"
```

建议提交前至少完成：
- 前端 `tsc` 与 `build`
- 后端 `compileall`
- Rust `cargo check`（若改了 `src-tauri`）
